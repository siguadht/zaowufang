# 造物坊 PRD · Bot 团队版

状态：可体验版本（2026-10-02）

## 1. 目标与定位

造物坊是一个桌面 AI 工作台，服务于产品构思、编码、验收和日常办公。用户在同一个应用里选择有清晰身份的 Bot 发起任务，并将选定工作区作为文件和代码的上下文。它希望逐步发展为“产品工厂”；当前版本的阶段切换需要用户手动确认和发起。

## 2. 目标用户与主要场景

- 独立创作者：从想法形成 PRD，再在本机工作区制作 MVP。
- 产品经理：整理需求、验收标准和交接资料。
- 开发者：依据已确认需求编辑代码并运行相关检查。
- 办公用户：研究、整理资料、生成报告。

## 3. 核心流程

1. 用户在首页选择产品 Bot，输入想法，可选择工作区。
2. 产品 Bot 输出 PRD 与验收标准；用户审阅并确认。
3. 用户选择开发 Bot，提供已确认 PRD 或其工作区路径；开发 Bot 实现并报告改动与验证。
4. 用户选择测试 Bot，提供交付物与验收标准；测试 Bot 核查并反馈缺陷。
5. 用户决定是否修复、再次验收或自行发布。办公 Bot 可独立处理研究与文档任务。

当前会话之间不自动传递审批状态。交接摘要、文件和工作区由用户选择或输入；不应将人工确认写成自动流水线。

## 4. 本版功能需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F1 | 首页展示四位 Bot 的独立形象、名称和职责 | 四位均可见；可点击选择；被选中状态清楚 |
| F2 | Bot 接入原有会话创建与模型配置 | 选中后发送任务创建对应助手的真实会话；未配置模型时给出原有配置路径 |
| F3 | Bot 有不同规则和示例任务 | 产品、开发、测试、办公的规则与示例内容不同；规则随安装包提供 |
| F4 | 保留既有助手、工作区、技能、模型和附件入口 | 四位 Bot 不阻断原有入口和能力 |
| F5 | 明确交付边界 | 文案说明模型/API 需用户配置，自动阶段流转及自动上线暂不支持 |
| F6 | 任务列表使用现有真实会话 | 可搜索、按运行／等待确认／空闲状态筛选，并进入原会话；不把会话状态当作项目完成状态 |
| F7 | 交付物页浏览任务工作区文件 | 选择真实会话后可浏览文件夹、刷新并预览文件；明确这些是工作区文件，未自动判定为最终交付物 |
| F8 | Bot 使用按职责配置的 Skill | 开发 Bot 配 UI 与项目实现 Skill；办公 Bot 配 PPT 与文章写作 Skill；PPT 生成依赖 OfficeCLI |

## 5. 设计要求

- 白色背景、黑色主按钮、中性灰层级。
- 品牌标识采用用户提供的第三款 F 字模，深蓝灰主形与蓝色方块；应用、侧栏和网页图标统一。
- Bot 形象借鉴用户提供的彩色扁平圆角三角大眼睛角色参考，并使用独立生成素材；蓝色产品、橙色开发、紫色测试、粉色办公。
- 大屏四列、小屏两列；键盘与辅助技术可识别选择状态。
- 原有“造物坊”窗口、应用图标与侧栏品牌保持统一。
- 侧栏按“新建任务、工作台、任务列表、交付物、Bot 团队、最近任务”组织，工具入口继续可用。

## 6. 非功能要求

- 支持项目已有的 13 种界面语言键；中文优先，其他语言可暂用英文文案。
- 原有设置、会话和模型数据不因新增 Bot 损坏。
- 保留原项目及上游许可、版权与来源声明。
- 发布前检查 TypeScript、多语言、前端构建、Rust 内置资源及安装启动。

## 7. 已知限制与后续版本

- 需要外接模型 API 或已支持的本地模型才能执行 AI 任务。
- 当前流程属于“分工明确、人工交接”的产品工厂雏形；缺少统一项目状态、交付物版本、审核闸门、Bot 间自动交接及一键部署。
- 任务列表的状态来自会话运行信息；交付物页展示工作区文件，不自动识别最终版本或验收结论。PPT Skill 在新设备上还需要可运行的 OfficeCLI。
- 后续优先加入项目级流程看板和阶段交接单，再评估部署集成。官网建议等安装体验和核心流程稳定后再做介绍页；当前优先提供 GitHub 私有仓库、安装包与体验说明。
